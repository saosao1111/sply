# 协议接入

本页面向钱包、机器人、终端、索引器和第三方数据方，说明应该如何接入 SPLY。

## 基础网络信息

- Network: `BNB Smart Chain Mainnet`
- Chain ID: `56`

正式部署地址见 [已部署合约地址](./deployed-contract-addresses.md)。

## 最重要的链上入口

对于集成方来说，最重要的合约不是单一 token，而是平台工厂体系：

- `LaunchFactory`
- `TemplateFactory`
- `FactoryAdmin`

这些地址决定了：

- 项目是如何创建的
- 模板是如何注册的
- 平台正式入口在哪里

## 项目与代币的关系

SPLY 不是简单地“发现一个 token 地址”。对外集成时，更稳定的方式是围绕项目对象建立映射：

- project id
- presale
- token
- vault
- pair

平台前端和后端都是按这个模型聚合数据的。

## 优先使用平台 API，而不是自己重建全部状态

如果你的目标是：

- 展示项目列表
- 展示单项目详情
- 展示 token 市场数据
- 展示交易记录

优先建议使用平台 API。这样可以直接获得已经整理过的结构，而不需要自己从多个合约与多个事件中重新拼装。

## 什么时候需要直接读链

以下场景更适合直接读链：

- 你要自己验证项目状态
- 你要做更底层的索引
- 你要确认 token 最终公开状态
- 你要对接自己的监控和告警系统

## 接入时应该重点关注什么

- 项目创建来源是否来自正式工厂
- 模板是否来自正式注册模板
- 项目是否已经 finalize
- token 是否已进入可交易状态
- pair 是否已建立

## 对钱包与终端开发者的建议

- 优先把项目页和代币页当成两个阶段，而不是一个阶段
- 预售阶段和公开交易阶段使用不同展示逻辑
- 把项目与 token 的映射关系保留下来，避免只按 symbol 或 token address 做弱关联
