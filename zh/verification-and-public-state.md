# 验证与公开状态链路

本页说明平台如何把一个 finalized 项目推进到公开可验证状态，以及外部平台通常会读取哪些链上输入。

## 1. 项目 finalize 完成

一个项目进入公开状态的前提不是“创建成功”，而是 finalize 完成。finalize 之后，项目会进入标准市场状态：

- LP 已建立
- 交易已开启
- 临时权限已清理
- token 可以进入验证流程

## 2. 后端 watcher 扫描 finalized 项目

平台后端会扫描已 finalized 的项目，并把新 token 推入验证队列。这意味着自动验证不是孤立脚本，而是平台状态机的延续。

## 3. source-verify 解析验证配置

验证服务默认支持平台标准 token，同时也会识别 custom core 的验证元数据。平台会根据 token 暴露的信息确定：

- 源码路径
- 合约名
- 对应 build info

然后再把验证请求提交到区块浏览器。

## 4. 平台能控制的“公开状态输入”

平台不能控制第三方平台的缓存速度，也不能控制所有第三方风控展示规则，但平台能控制自己输出到链上的关键状态：

- source verified
- owner 收口
- presale 地址清理
- 关键参数锁定
- LP burn
- trading enabled

这些才是外部平台最终读取和消费的输入。

## 5. 为什么平台关心这条链路

如果 finalize 完成后没有后续验证链路，项目虽然能交易，但平台对“公开状态”就没有产品能力。

SPLY 的目标不是只完成链上动作，而是尽量把项目推进到：

- 可交易
- 可验证
- 可展示

这三件事同时成立的状态。

## 6. 对外部展示结果应如何理解

外部平台的页面展示不一定实时，也不一定完全一致。平台能确保的是：

- 链上状态路径正确
- 自动验证链路正确
- 公开状态输入尽量完整

至于不同第三方平台多久刷新、如何解释这些状态，是平台外部因素。
