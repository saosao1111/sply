# 开发者模板指南

本页说明开发者如何把自己的模板接入 SPLY，并让模板在审核通过后成为平台正式可用模板。

## 开发者模板的目标是什么

开发者模板的目标不是让开发者绕开平台，而是让开发者把自己的代币机制接入平台标准：

- 继续走平台发射路径
- 继续服从平台审核与注册
- 继续进入平台模板列表
- 继续共享平台地址规划和验证能力

## 一个模板由什么组成

在 SPLY 里，一个开发者模板至少包括两部分：

- deployer
- token core 或 token core 部署逻辑

deployer 负责解码模板参数、生成 token core，并向平台暴露必要的接口。

## 开发者提交流程

开发者提交模板时，需要提供：

- deployer 地址或部署方案
- 模板名称与说明
- 参数结构说明
- 审核所需的补充资料

提交后，模板会进入后台待审核队列，而不是立即公开。

## 审核通过后会发生什么

管理员在后台审核通过后，会通过 `FactoryAdmin` 把模板注册到平台。注册成功后：

- 模板会出现在平台的公开模板列表中
- 项目方可以在创建页选择这个模板
- 模板会按平台规则参与发射

## 必须满足的接口约束

当前平台对 custom token core 有明确接口要求。模板需要让 token core 能够配合平台流程完成：

- `setPresale`
- `setTaxStrategy`
- `setMarketConfig`
- `enableTrading`
- `lockAfterFinalize`
- `renounceByPresale`
- `clearPresale`

如果模板不满足这些接口，就无法与平台 finalize 流程正确衔接。

## 平台为什么要限制这些接口

因为开发者模板不是完全独立的链上产品，而是平台模板。平台必须确保：

- 预售资金仍由平台管理
- finalize 路径仍然成立
- 临时权限可以在标准时点清理
- token 可以进入平台验证链路

## 平台 custom core 路径

当前正式架构支持开发者模板进入平台统一 `CREATE2` 部署路径。对模板来说，这意味着：

- 模板不再一定要自己部署 token
- 模板可以让平台负责地址规划和部署
- 模板上线后仍然能走平台的 deterministic 发射能力

## 模板设计建议

- 让 deployer 只负责部署与初始化，不要把平台逻辑硬编码进模板
- 不要让 token core 直接接触 Vault 资金
- 不要在模板里留隐藏 mint、黑名单或绕过 finalize 的后门
- 参数用 `abi.decode` 明确定义，不要把关键参数硬编码死
- 把模板接口设计成能被平台验证和平台维护

## 提交前的自检问题

- 这个模板是否真的走平台发射，而不是绕平台发射
- token core 是否满足平台接口
- 模板参数是否清晰、可验证、可审核
- finalize 后状态是否能正确收口
- 是否能配合平台的验证与展示链路
