# 发射流程概览

本页从产品视角说明一个项目从创建到进入公开交易的大致流程。更底层的调用链见 [发射流程内部机制](./launch-flow-internals.md)。

## 1. 项目方创建项目

项目方在创建页提交：

- 代币名称与符号
- 总量
- 预售价格
- 软顶与硬顶
- 单笔与单钱包限制
- 结束时间
- Logo、描述与社交链接
- 代币机制模板

如果是平台内置模板，平台按内置模板逻辑处理；如果是已审核通过的开发者模板，平台按开发者模板的 deployer 规则处理，但仍然走平台统一发射路径。

## 2. 平台建立项目主体

项目创建后，平台会建立项目级对象，包括：

- token
- vault
- presale

项目页随后可以展示募资状态、配置信息和参与入口。

## 3. 用户参与预售

参与者向项目预售入口提交 BNB。资金进入 `Vault`，`Presale` 更新状态并记录参与信息。

平台当前的预售结构不是“先募资、后统一发币”，而是把代币分发与 LP 预留绑定在同一条公式里，确保 finalize 阶段可以用一致的方式完成后续处理。

## 4. 达到条件后进入 finalize

当项目达到 hard cap，或满足平台的 finalize 条件时，项目进入 finalize 流程。这个阶段会把一系列关键动作收束到一条链路里处理：

- 计算平台费
- 建立 PancakeSwap V2 流动性
- 获取 pair 地址
- 写入 token 的市场配置
- 开启交易
- 锁定关键参数
- 清理临时权限
- 销毁 LP

## 5. 项目转入公开交易阶段

finalize 完成后，项目不再只是一个募资项目，而会切换为公开可交易的 token。此时代币页开始承接：

- 市场数据
- 流动性快照
- 最近交易
- 买卖入口

## 6. 自动验证与公开展示

平台后台会监听 finalized 项目，并把 token 送入自动验证流程。随后前台和外部平台可以逐步拿到更完整的公开状态输入。

## 这套流程的重点是什么

重点不是“把这些动作做完”，而是让所有模板都尽量走同一套闭环：

- 募资路径统一
- finalize 路径统一
- 开盘状态统一
- 验证入口统一
- 前台展示入口统一

这也是为什么 SPLY 能同时支持内置模板和开发者模板，而不需要把整个平台拆成多套系统。
