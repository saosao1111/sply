# 欢迎来到 SPLY

SPLY 是一套运行在 BNB Smart Chain 上的模板化发射平台。它不是单一的发币页面，也不是只负责部署代币的脚本集合，而是一条从创建、募资、托管、开盘、验证、展示到模板审核的完整发射流程。

当前文档基于平台现有代码与页面结构整理，面向四类人群：

- 项目方：希望在统一流程里发起预售并进入交易市场
- 机制开发者：希望把自定义代币逻辑接入平台，作为正式模板供所有人使用
- 参与者与交易用户：希望通过统一项目页和交易页了解募资、市场和交易状态
- 钱包、终端、机器人、索引与数据集成方：希望按稳定接口和稳定状态读取平台数据

## SPLY 是什么

SPLY 的核心价值不是“帮用户部署一个代币”，而是把发射台里最容易分散、最容易出错的部分收拢成平台标准：

- 代币部署方式统一
- 预售资金托管方式统一
- 开盘与权限收口方式统一
- 模板审核与模板注册方式统一
- 前台、后台与链上状态的一致性尽量统一

这意味着，项目方可以在平台里选择不同机制，但不需要自己重新拼一套发射流程；开发者可以扩展代币逻辑，但不能绕开平台的资金托管与发射标准；外部集成方可以按稳定地址和稳定 API 读取数据，而不是追着每个模板的实现细节跑。

## SPLY 解决什么问题

在 BSC 上发一个币并不难，难的是把整条发射链路做成可重复、可审计、可扩展的产品：

- 项目方往往要分别处理代币部署、募资、LP 建立、交易开启、权限清理和源码验证
- 不同模板一多，平台很容易退化成“每个模板一套规则”
- 预售资金和模板逻辑如果混在一起，扩展能力和安全边界都会变差
- 代币上线后，外部平台是否能快速识别开源、弃权、锁池、交易状态，取决于链上状态是否足够统一
- 当平台开放给开发者上传模板后，如果没有审核、注册、地址规划和验证标准，最终会重新回到“每个模板各管各的”

SPLY 的设计目标就是解决这些问题。平台要支持更多模板，但又不能让更多模板破坏平台标准。

## 核心优势

## 1. 统一发射标准

SPLY 把发射拆成明确的角色：

- `LaunchFactory` 负责建立项目主体
- `TemplateFactory` 负责模板分流与模板调用
- `Presale` 负责募资状态机
- `Vault` 负责资金托管
- token core 负责代币行为
- `FactoryAdmin` 负责模板管理与治理配置

这样做的结果是，平台不是“让某个模板自己完成一切”，而是让模板嵌入平台流程。对项目方来说，模板是代币机制的差异，不是整条发射流程的差异。

## 2. 资金托管与代币机制分离

SPLY 把资金放进 `Vault`，把募资状态放在 `Presale`，把代币行为放在 token core。模板可以改变代币逻辑，但不能直接控制预售资金，也不能绕开平台的 finalize 流程。

这种分离的价值很直接：

- 扩展模板时，不需要重写资金托管逻辑
- 审核模板时，可以把注意力放在代币行为，而不是所有平台资金路径
- 平台可以在不放弃控制边界的前提下开放模板能力

## 3. 平台级地址规划能力

SPLY 的正式架构支持平台统一的 `CREATE2` 发射路径，并且会针对不同 token core 维护独立盐池。平台不是“随机发一个地址”，而是把确定性部署作为平台能力来管理。

这带来的好处包括：

- 地址预测是平台能力，而不是模板私有能力
- 不同 token core 可以独立维护地址规划
- 开发者模板可以继续走平台发射，而不是脱离平台单独部署

## 4. 开盘与状态收口在一条链路里完成

SPLY 不是“募集完成后剩下的事情项目方自己处理”。当项目进入 finalize 流程后，平台会把以下事情收束到统一链路中：

- 处理平台费
- 建立 PancakeSwap V2 流动性
- 获取 pair 地址
- 写入 market config
- 销毁 LP
- 开启交易
- 锁定关键参数
- 清理临时权限
- 进入自动验证队列

这意味着平台要管理的不只是“发币成功”，而是“发币后进入标准市场状态”。

## 5. 开发者模板是平台一等公民

从当前架构开始，开发者模板不再是平台外的附加物。一个模板如果满足平台要求、通过后台审核并注册成功，就会进入平台的正式模板列表，供所有用户使用。

这件事的关键不在“能上传一个合约”，而在于：

- 上传后的模板仍然走平台发射流程
- 仍然进入平台的地址规划体系
- 仍然能走自动验证链路
- 仍然接受平台的审核与开关控制

## 6. 前台、后台、后端与链上状态是连通的

SPLY 不是只有一个创建页。平台还有：

- 首页与项目列表
- 模板页
- 开发者页
- 项目详情页
- 代币交易页
- 后台审核页
- 数据 API
- 自动验证与项目索引服务

这意味着平台既是链上协议，也是一整套运营与展示系统。
